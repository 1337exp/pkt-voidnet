# pkt-voidnet

[English](README.md) · **Русский**

Небольшое самостоятельное сетевое ядро для игр: соединения, режимы доставки, устойчивость к враждебному вводу. Ничего не знает об игре, которая построена на нём.

**Статус: этапы 1-3 готовы: соединения работают и несут данные в трёх режимах доставки, в симуляторе.** Формат на проводе, рукопожатие и допуск, а теперь и доставка: надёжный упорядоченный, ненадёжный и ненадёжный «только свежее» каналы, подтверждения, едущие вместе с данными, RTT, восстановление после потерь, таймеры проб с удлинением, keep-alive. К настоящему сокету и к игре пока ничего не подключено: дальше C ABI и фасад Tee (этап 4).

## Стек

- Ядро: Rust, по возможности `no_std`, наружу C ABI.
- Первый потребитель: игра Tee на Zig (фасад на Zig поверх ядра).
- Цели дизайна: изоляция, минимальный размер, тестирование без сети (sans-IO), слои, которые подключаются по желанию.

## Команды

```bash
cargo test --workspace                        # юнит-тесты, свойства, имитатор
cargo clippy --workspace --all-targets
zig test vectors/check.zig                    # независимый декодер на Zig против vectors/wire-v1.txt
UPDATE_VECTORS=1 cargo test -p voidnet-core --test vectors   # пересоздать векторы после изменения формата
# библиотека C ABI для Zig под Windows и проверка линковки:
cargo build -p voidnet-ffi --release --features abi --target x86_64-pc-windows-gnu
(cd tests/zig-abi && zig build run -Dtarget=x86_64-windows-gnu)
```

Цели фаззинга: `parse_datagram`, `recv_window`, `ack_frame`, `handshake_flood`, `conn_stream`. Для фаззинга нужен nightly и, на Windows, ASAN-рантайм Visual Studio в `PATH` (см. `spike/RESULT.md`): из `fuzz/` команда `cargo +nightly fuzz run parse_datagram`.

## Как устроено

- `docs/wire.ru.md`: единственное нормативное описание байтов. `vectors/wire-v1.txt`: строки байтов с каноничным прочтением.
- `crates/voidnet-core`: `no_std`, без выделения памяти, `forbid(unsafe_code)`, индексирование и `unwrap` запрещены линтом. Разбор формата, окно номеров, кадры ACK, соединение (`Conn`: доставка, RTT, потери, таймеры), автоматы `Server` и `Client`. Около 100 КБ на соединение, фиксированно.
- `crates/voidnet-sim`: ГСЧ с зерном, канал с потерями (потери, дубли, перестановка, блэкаут), маленький мир из сервера и клиентов, пара голых соединений, эталонные хеши трасс, сценарии атак, потерь и таймеров.
- `crates/voidnet-ffi`: C ABI, `unsafe` живёт только здесь.
- Проектирование и обоснования: спецификация сетевого ядра в репозитории Tee (`docs/architecture/netcore-spec.md`).

## Пока нет

- C ABI поверх `Server` и `Client` (инициализация на месте в памяти хозяина), фасада Tee, скрипта сборки под каждую ОС (этап 4).
- Полного C ABI, скрипта сборки под каждую ОС и обвязок.
